# Asterion Control — native assistant reconstruction (2026-11-26)
Status: urgent source work, not a release. Canonical V6 and V3/V4/V5 non-conflicting requirements remain binding. The November 19 owner release hold still forbids interim APKs/transfers; this branch preserves production.
## Purpose
Reproduce useful product-level capabilities of a general assistant through original open-weight model adaptation and executable tools, not proprietary GPT weights, private prompts or training data. Qwen3 0.6B is the known inadequate baseline; no model is promoted by name or size. One or two general models, same assistant identity/memory across clients. No mandatory paid service. Local ordinary use must work independently of PC and ChatGPT. Heavy PC inference is optional.

## Model implementation path
1. Evaluate non-Qwen candidates on actual Samsung, initially SmolLM3-3B (HuggingFaceTB/SmolLM3-3B) and Ministral-3-3B-Instruct-2512; verify official licenses, pin revisions/hashes, quantify RAM/thermal/latency, audit templates and current pinned llama.cpp support. This is a candidate shortlist, not a decision or claim of runtime compatibility.
2. Replace hardwired model metadata/template/context limits with validated registry and model-native chat template, genuine streaming, cancellation and context budgeting. Preserve signature, existing runtime, model identity, jobs and WSS.
3. Adapt selected local weights from licensed base using original examples in all capability domains; actual trained LoRA candidate produced by scripts/control_ai_adaptation.py only after hardware, data rights, split and tokenizer checks. Do not claim weights from code alone. Maintain exact base/adapter hashes and provenance. No automatic production replacement.
4. Integrate real tools, memory, streaming, retrieval and postcondition verification with original native services. A model cannot independently acquire new OS permissions or credentials.
5. Export/merge compatible adapter and quantize using matching vetted llama.cpp converter. Verify exact GGUF and native ABI, install only after owner release criteria. Evaluate raw base vs adapted vs Qwen baseline on identical tasks. No release if regressions or resource failures.
## Gates and deadline
Before Dec 1: prioritize working useful offline inference and model-independent runtime, source-level tool/memory integration, exact verified baseline, candidate benchmark, test/correction and merge-safe interfaces. No fake completion or guaranteed parity/deadline. Actual installed standalone acceptance requires owner-authorized release after source completion. Model Lab maturity target remains >=50k distinct sealed holdout, >=200k separate stress, >=2k real integrated workflows, >=1k human-reviewed quality cases. Exact split validation is necessary but not semantic contamination proof. Small smoke tests are engineering checks only, not quality certification. Full GPT-6.2-class general reasoning and proprietary multimodal/service parity are not guaranteed by 3B weights, and from-scratch frontier training is infeasible on the measured hardware. No compulsory cloud, new pairing or additional app.
